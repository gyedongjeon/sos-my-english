## Request

Start `sos-my-english`, an English learning app centred on speaking, as the first branch of the
repository. It is released as a series product next to `sos-my-interview` and should be a
desktop app much like it, so that project's source may be reused freely.

## Changes

- **Reused from `sos-my-interview` (v0.2.1)**, renamed and otherwise unchanged: the SOS theme and
  brand components, the Settings page (feedback language, model and API key), the LiteLLM
  wrapper, local Whisper transcription, the local Kokoro voice with its cache and browser-voice
  fallback, the Electron shell with the bundled `uv`, in-app updates from GitHub releases
  (as of v0.3.0, with its tests), the CI and release workflows, and the git-workflow documents,
  worklog template, and `AGENTS.md`. Environment variables use the `SOS_MY_ENGLISH_` prefix, and
  the version starts at `0.1.0`.
- **Left out**: everything specific to interviews (questions, attempts and history, résumé and
  job postings, scoring), the camera, and live captions. The dependencies only those needed
  (`lxml`, `pypdf`, `trafilatura`, `@types/dom-speech-recognition`) were removed, and the desktop
  app asks for the microphone only.
- **New: spoken conversation.** Topics are seeded in the database, each with a situation and the
  tutor's opening line (`GET /api/topics`). `POST /api/reply` takes the conversation so far and
  returns the tutor's next line with at most one correction of the learner's latest message; the
  correction is explained in the feedback language. One model call returns both, as JSON, to
  keep the wait between turns short. The conversation is kept in the page (a Pinia store) and is
  not saved yet; history was left for a later branch.
- **Practice page**: the tutor's line is read aloud and its text stays hidden until asked for;
  the learner records a reply, which is transcribed with its clarity, unclear words, and pace;
  the correction is shown under the learner's line and can be played. If the reply request
  fails, the learner's line is kept and the reply can be asked for again.
- **App icon**: the series' life ring with a speech-bubble tail on the same navy tile, so the
  app can be told apart from `sos-my-interview` in the Dock. `desktop/assets/icon.svg` is the
  source and `icon.png` is rendered from it with `desktop/scripts/render-icon.sh`.
- **Name in development**: `npm run dev` runs Electron's own bundle, which the Dock labelled
  "Electron". `desktop/scripts/name-dev-app.mjs` now writes the product name into that bundle
  and renames the bundle itself (the Dock labels an app by its bundle's file name) before the
  app starts. The packaged app was already named correctly.
- **Spoken, not written**: a correction that only changes punctuation or capitals (for example
  adding a question mark) is dropped, and the model is told never to make one, because those
  come from speech recognition, not from the learner.
- **Brought over from `sos-my-interview` v0.4.0 and its two later merges**:
    - One folder for everything: the Whisper model is downloaded into the data folder instead
      of the shared Hugging Face cache (with its Xet transfer turned off), and the packaged app
      points uv's cache and its Python at the app's own folder, so deleting
      `~/Library/Application Support/SOS My English/` removes everything the app put on disk.
      The backend launch moved into `desktop/src/backend.ts`, with tests.
    - The speech models are downloaded when the app opens, with progress shown under the
      navigation bar and a "Try again" button on failure (`GET /api/models`,
      `POST /api/models/download`); a recording made before speech recognition is there waits
      for it and says so.
    - `tenacity` is installed, so a failed LLM request is retried and reported by its cause.
    - `backend/.env.example`, and three live tests (`pytest -m live`) with their own CI job:
      a reply fit to be read aloud, a correction explained in the chosen language, and no
      correction for missing punctuation.
- **In-app updates**: the packaged app looks for a newer release of this repository at startup
  and from "Check for Updates…", and replaces itself after a click; the release workflow also
  publishes the `.zip` it downloads. Nothing can be offered until a first release exists.

## Verification

- `cd backend && uv run pytest`: 65 passed, 3 live tests deselected.
- `cd frontend && npm test`: 26 passed; `npm run build` (type check and build) succeeded.
- `cd desktop && npm test`: 29 passed; `npx tsc --noEmit` succeeded.
- Started the backend against a temporary data folder with the built frontend: `/api/health`,
  `/api/topics`, and the client-side route `/topics/1` answered as expected, and `/api/reply`
  without a configured model returned the "No model is configured" message.
- The rendered icon is 1024 x 1024 and was looked at. `npm run package` built the app bundle; it
  contains `icon.icns` named in `Info.plist`, the bundled `uv`, and a valid ad-hoc signature.
- Ran the desktop app with `npm run dev`: the Dock labels it "SOS My English" (read from the
  Dock), `/api/models` reported both models ready in `backend/data`,
  and a spoken turn was transcribed and answered with a correction. With the voice model
  downloaded, `/api/speech` returned WAV audio in under 3 seconds; before that, the built-in
  voice started and finished speaking the opening line on the practice page.
- Not verified: the live tests (no key was used here; the CI job needs the `GEMINI_API_KEY`
  secret); the download banner while a download is running; that the tutor's voice is audible in the app (one run reported no sound while
  the voice model was still downloading, and the cause was not found); the packaged bundle
  with its downloads in the app's own folder; the `.dmg` and `.zip` targets (`npm run dist`);
  and an update between two published releases, since there is no release yet.
